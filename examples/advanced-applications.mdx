## Cross-subject training

Combine calibration data from multiple users, then personalize to a new user with a small labeled set. When a frozen trunk already transfers, prefer [`Personalizer`](/personalizer/overview) + per-user calibration over full fine-tuning.

Core workflow:

1. Extract the same feature type (or freeze the same encoder) for every subject.
2. Normalize using training subjects only.
3. Train a conservative baseline (`Personalizer(head="lda")` or `NimbusLDA`).
4. Evaluate with subject-wise splits, not random trial splits.
5. Personalize with a small calibration set for the target subject.

<Tabs>
  <Tab title="Python">
```python
from nimbus_bci import Personalizer, wrap, estimate_normalization_params, apply_normalization
from sklearn.model_selection import LeaveOneGroupOut

# Frozen trunk path — same encoder for all subjects
enc = wrap(model.encode, model_id="shared-trunk", embedding_dim=64)

X, y, groups = load_multi_subject_features()  # or embeddings from enc
logo = LeaveOneGroupOut()

for train_idx, test_idx in logo.split(X, y, groups):
    norm = estimate_normalization_params(X[train_idx], method="zscore")
    X_train = apply_normalization(X[train_idx], norm)
    X_test = apply_normalization(X[test_idx], norm)

    adapter = Personalizer(
        encoder=None,  # features/embeddings already prepared
        head="lda",
        classes=["left", "right"],
        preset="research",
    )
    adapter.fit(X_train, y[train_idx])
    states = adapter.predict(X_test)
    # score from labels when available; gate on states[*].confidence in apps
```

## Hybrid BCI

Hybrid BCIs combine evidence from multiple paradigms, such as motor imagery plus P300.

Recommended pattern:

- Keep one Personalizer / head per paradigm (or one frozen trunk + head).
- Normalize each feature family separately.
- Combine posterior probabilities or confidence-weighted decisions.
- Log disagreement between paradigms for later review.

```python
mi_states = mi_adapter.predict(mi_features)
p300_states = p300_adapter.predict(p300_features)

# Or combine head posteriors for research fusion
mi_proba = mi_adapter.head.predict_proba(mi_features)
p300_proba = p300_adapter.head.predict_proba(p300_features)
combined = 0.6 * mi_proba + 0.4 * p300_proba
```

Use conservative thresholds for high-stakes actions and require confirmation when paradigms disagree. App gates: [BrainState](/personalizer/brain-state).

## Continuous control

Continuous control maps repeated predictions into a smoothed command stream.

```python
alpha = 0.3
smoothed = None

for state in brain_state_stream:  # or posterior_stream from a head
    command = posterior_to_velocity(state.posterior)
    smoothed = command if smoothed is None else alpha * command + (1 - alpha) * smoothed
    if not state.rejected:
        send_control(smoothed)
```

Keep smoothing outside the classifier. The model reports uncertainty; the control layer decides how aggressively to act.

## Adaptive learning

Adaptation is useful when signal distributions drift during long sessions or across days.

| Signal | Pattern |
| --- | --- |
| Which trials to label | [Active Learning](/python-sdk/active-learning) / `CalibrationSession` |
| Whether to stream-update | `Personalizer.recommend_adapt(..., tau=...)` then `partial_fit` |
| Trial accept / reject | `BrainState.rejected` / `need_more_data` |
| Non-stationary state | `NimbusSTS` / `StreamingSessionSTS` |

```python
dec = adapter.recommend_adapt(X_stream, tau=your_tau)
if dec.should_adapt:
    adapter.partial_fit(X_lab, y_lab)

states = adapter.predict(X_eval)
# optional: state.extras.update(dec.to_extras())
```

See [Personalizer overview](/personalizer/overview) for adapt vs trial gates, and [Active Learning](/python-sdk/active-learning) for label selection.

## Multi-session experiments

For experiments that span days or weeks:

- Use a stable preprocessing / encoder pipeline and save its parameters (`model_id`, `embedding_dim`).
- Save normalization parameters with each trained profile (`Personalizer.save` / head artifacts).
- Track hardware, montage, impedance, session time, and participant state.
- Evaluate same-session and cross-session performance separately.
- Compare adaptation against a no-adaptation baseline.

Suggested metadata to log:

```json
{
  "subject_id": "S001",
  "session_id": "2026-04-25-AM",
  "paradigm": "motor_imagery",
  "model_id": "partner-encoder",
  "head": "lda",
  "feature_type": "embedding",
  "normalization": "zscore",
  "sampling_rate": 250
}
```

## Robust deployment

Production systems should separate personalization, control, and safety policy:

1. Personalizer returns `BrainState` (intent, posterior, confidence, gates).
2. Quality gate accepts, rejects, or asks for more data (`need_more_data`).
3. Control layer maps accepted intents to actions.
4. Monitoring logs confidence, latency, rejection rate, and drift.

```python
for state in adapter.predict(X_online):
    if state.rejected or state.need_more_data:
        reject_or_ask_more(state)
    elif state.confidence >= 0.9:
        execute(state.intent)
    elif state.confidence >= 0.7:
        request_confirmation(state.intent)
    else:
        reject_or_ask_more(state)
```

For detailed safeguards, see [Error Handling](/inference-configuration/error-handling) and [BrainState](/personalizer/brain-state).
