Nimbus middleware is the **product wedge**: a Bayesian personalization head for **frozen neural / foundation embeddings**. Encoders stay external. Apps consume thin `BrainState` outputs.

**One-liner:** anything that maps trials to embeddings plugs in; Nimbus owns personalization, uncertainty gating, and cheap online updates — not the trunk.

<Tip>
  **Product takeaway (Paper 1):** ship one Personalizer; treat fine-tune as a **priced escape hatch**, not the default integration path. Use the head where embedding capacity exists; stay cal-only when clean already wins.
</Tip>

_Why the hatch stays priced: across classical trunks, stream Personalizer (L1) recovers most of the L0→L3 gain and usually beats a matched linear probe — details on [Evidence](/personalizer/evidence)._

## Ladder legend (plain language)

| Label | What it is | Shipped? |
| --- | --- | --- |
| **L0 — calibration-only** | Fit the Bayesian head on calibration data once; no stream updates | Yes — fit once |
| **L1 — stream head** | L0 + online head updates on new labeled trials | Yes — default product path |
| **LP — linear probe** | Logistic regression on the same frozen embeddings | Bench control (not a Personalizer head) |
| **L2 — affine map + head** | Supervised affine map on embeddings, then the head | Opt-in via `transform="affine"` / `fit_affine()` (research / offline; not deployment default) |
| **L3 — full fine-tune** | Warm-start fine-tune of the encoder | Escape hatch (outside Personalizer; priced); `[train]` PEFT / BaLoRA opt-in |

Blue `rec %` on the figure = how much of the **L0→L3 accuracy gain** L1 recovers: `(acc_L1 − acc_L0) / (acc_L3 − acc_L0)`. `≥FT` means L1 matches or beats L3.

How the Paper 1 / 1b numbers were produced (datasets, bandpass, session split, synthetic stress): [Evidence → How the experiments work](/personalizer/evidence#how-the-experiments-work-data-flow).

<Info>
  Classical CSP / bandpower / Riemann features still work. Use `Personalizer.for_features(...)` or the standalone heads (`NimbusLDA`, …) documented under [Models](/model-specification). Upgrading from 0.5? See [Migration to 0.6](/python-sdk/migration-0.6).
</Info>

## Minimal example

```python
from nimbus_bci import Personalizer, wrap

enc = wrap(model.encode, model_id="partner-encoder", embedding_dim=64)
# for_deployment = strict gating + LDA (common production case).
# Pin accept rate with fit_calibrated(...) when default gates don't match your trunk.
adapter = Personalizer.for_deployment(
    enc, ["left", "right"], paradigm="motor_imagery"
)
adapter.fit(X_cal, y_cal)
states = adapter.predict(X_test)  # list[BrainState] or BrainStateBatch
```

Other factories: `for_research` (permissive + knobs), `for_features` (no trunk), `for_riemann` / `for_p300` (`nimbus-bci[riemann]`), `for_balora` (`nimbus-bci[train]`). Paradigm recipes and day-2 profiles: [Paradigms & profiles](/personalizer/paradigms).

## Integrator checklist

1. **When to adapt** — prefer the adaptation gateway, or the thin mean-shift helper with a **user-supplied** threshold:

```python
# Label-agnostic gateway (head / transform / trunk PEFT)
adapter.adapt(X_new, y_new)  # or y=None for unsupervised paths

# Optional: decide whether to spend labels on a stream update
dec = adapter.recommend_adapt(X_stream, tau=your_tau)
if dec.should_adapt:
    adapter.partial_fit(X_lab, y_lab)
```

Policy: stay on the current head when clean; stream-update when shift clears `tau`; full fine-tune stays a manual escape hatch. Portable day-2 warm-start: `export_profile()` → `from_profile(...)`. See [Evidence](/personalizer/evidence).

2. **Trial gate (different signal)** — `preset="strict"` / `"permissive"` (0.6 rename; was `research` / `consumer`); inspect `BrainState.rejected`, `need_more_data`, `uncertainty`. See [BrainState](/personalizer/brain-state).

3. **Head stability** — after online updates, use `calibration_sufficient` / `calibration_status` on an unlabeled pool.

4. **Encoder swap** — freeze trunk; match `embedding_dim`; never pass logits as embeddings; keep `model_id` consistent across `save` / `load` / profiles. See [Encoder contract](/personalizer/encoder-contract).
